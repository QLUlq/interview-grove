## 二、一分钟项目介绍

我做的是一个叫“面向”的AI面试和项目理解练习应用。出发点是，我自己学习项目时，发现能把程序运行起来，并不代表能把功能怎样实现讲清楚，所以希望做一个帮助初学者练习理解和表达的工具。

它主要有求职和考研复试两个方向。求职可以上传项目文件夹或简历图片，系统先读取材料再安排问题；项目练习先问用途和功能流程，再逐步问模块协作与验证。复试则按照报考专业、408、信号与系统或自定义范围练习。

回答以后可以看复盘、修改回答并保留原记录，也可以单独重答一题。前端使用原生JavaScript，后端用Node.js，账号记录存SQLite，访客记录保存在浏览器。

这个项目是在AI编程工具辅助下完成的，我主要从自己的使用需求出发提出功能、反馈问题并参与体验验收。目前完成的是本机使用版，模型内容仍需要核对，语音识别也还有明显不足。

## 三、继续追问时的完整讲解

### 1. 为什么做

我的需求不是单纯获得一道面试题，而是检查自己能不能解释正在学习的项目。例如跟教程完成一个开源移植后，我可能知道有哪些功能，却说不清一次操作怎样经过几个模块。直接用聊天模型练习时，问题又容易跳到很细的函数名，或默认某个方案是我独立设计的。

所以这个应用主要解决两个问题：一是让问题结合实际材料，并从容易理解的功能流程开始；二是让复盘能继续变成下一次具体练习，而不是看完一大段建议就结束。

### 2. 用户怎么用

求职项目练习中，用户选择整个小项目或自己负责的模块，上传文件夹。前端过滤依赖、构建产物和明显的凭据文件，保留相对路径和代码片段，并展示读取与省略范围。后端把这些材料交给模型，整理带引用的功能模块，再生成本轮问题计划。

练习按照计划推进。用户提交回答后，后端先校验会话和当前可用动作，再让模型判断围绕本题补问还是进入下一题。程序会检查输出，而不是把模型说的下一步直接照搬到页面上。10、20、30分钟用于安排题量，不是强制倒计时。

结束后可以看整轮摘要、原答引用和逐题建议。发现某一题讲得不好，可以只重答这一题，生成保留原记录的分支，并比较前后回答。复试还支持按专业范围生成题组，选择题按AI参考答案整理错题，口头题由用户自评。

### 3. 前后端怎么协作

前端负责页面、表单、材料选择、当前练习展示和草稿交互。Node.js后端提供HTTP接口，处理账号、记录存储、模型调用、输出校验和本机语音请求。模型密钥只在服务端读取，不放到浏览器里。

一次AI问答的主要过程是：前端发送当前会话、回答与账号归属；后端检查请求和会话；整理当前问题、相关材料、用户明确说过的经历边界和允许动作；调用模型；校验返回JSON与引用；按照程序规则更新会话；前端展示结果，并通过保存接口落盘。

账号记录以JSON文本保存在SQLite用户记录中。它适合目前较小规模的本机应用，方便保留完整会话和分支，但不是适合复杂统计与大规模检索的数据结构。

### 4. 哪些地方有实际设计内容

第一是材料约束。代码片段与出处被保留，问题有依据，页面也会说明没有读到的范围。目前最多80个文件、约11万字符，不能说完整理解整个仓库。

第二是流程约束。问题先规划，再按状态和预算推进。项目10/20/30分钟对应4/6/8个主考察点，最多5/8/11次回答，深入追问也受到限制，防止只围绕一个点无限追问。

第三是事实约束。用户说明跟教程完成、没有做过某项测试或没有独立定位故障后，后续问题和润色要尊重这些边界。系统校验引用能否在原文找到，但这只能证明引用来自输入，不能证明技术结论一定正确。

第四是数据保留。草稿自动保存，重答保留原回答，删除原对话也不会级联删掉分支。账号保存按顺序发送，并检查版本号，避免较早的请求覆盖较新的草稿。

### 5. 做到了什么，没做到什么

目前本机文字练习、复盘与重练流程已经可用。收尾时自动测试111项通过，部分模型调用与页面流程也做过实际验证。这些证据说明相应接口和流程在测试条件下工作，不代表题目和建议都正确。

没有训练模型，没有使用向量数据库，也没有做生产部署、真实用户规模统计或高并发性能评测。语音链路已接通，但离线引擎识别技术词的效果不理想，因此只是辅助输入。

## 四、HR或综合面试常见问答

### 问题1：这个项目是你独立做的吗？你具体负责什么？

这个项目是在AI编程工具辅助下完成的，代码实现和部分验证借助了工具。我主要从自己的练习场景出发提出需求，反馈提问方式、复盘表达和页面使用中的问题，并参与体验验收。例如我希望项目提问先从功能流程开始，也提出了按专业开展复试练习、拆分两类历史记录、增加错题回练等需求。我不会把AI辅助完成的代码都描述成自己独立手写，目前也在继续理解各模块的实现。

### 问题2：为什么不直接用聊天软件？

聊天软件也能帮忙练习，但这个应用把材料、题量、会话进度、草稿和复盘接在了一起。比如上次没有讲清的一题，可以从原记录直接进入重答，而不用重新复制材料和对话。它的价值主要在练习流程和数据保留，不是底层模型比聊天软件更聪明。

### 问题3：你觉得最有价值的功能是什么？

对我来说是从复盘直接进入单题重答。看一份详细建议很容易觉得自己懂了，但真正重新组织一遍回答，才会暴露没有理解的环节。系统保留前后两次回答，方便具体比较哪里说清楚了，哪里还要查资料。提交一次重答只代表练了一遍，不等于已经掌握。

### 问题4：过程中遇到过什么问题？

一个实际遇到的问题是语音输入。最初浏览器识别出现连接失败，后来接入了Windows离线识别，但实际使用中又发现技术词和普通句子可能被识别错。这让我认识到，链路跑通和产品好用是两件事。目前保留键盘输入和系统听写作为使用方式，没有把语音识别包装成已经成熟的能力。代码层面的修改和排查借助了AI工具，我能确认的是这些实际现象与当前处理结果。

### 问题5：项目效果怎么样，有多少用户？

现在主要用于我自己的学习和本机验证，没有可报告的真实活跃用户数量、面试通过率或商业收入。已有111项自动测试通过，并验证过部分实际模型请求和页面流程，但还没有做全面的面试质量评测。当前能说明的是主要功能已经落地，不能据此宣称提高了多少求职成功率。

### 问题6：做完这个项目，你最大的收获是什么？

我更清楚地认识到，把模型接口接通只是开始。真正让人能持续使用，还要考虑回答会不会丢、模型失败时怎么办、问题是否适合当前水平，以及建议有没有超出用户真实经历。我也认识到，使用AI工具开发后仍然要理解关键流程，不能只看页面能运行就认为自己掌握了实现。

### 问题7：下一步会怎么改？

我会先围绕实际练习中的问题维护这一版，重点关注题目适不适合新手、建议有没有编造经历，以及保存与恢复是否可靠。语音需要另行比较识别方案和成本。暂时不会因为技术名词更多就加入复杂架构；当前本机规模还没有这方面的需求。

## 五、技术面试可能继续问的问题

### 问题8：为什么选择原生JavaScript、Node.js和SQLite？

这个项目首先服务于本机使用，目标是尽快跑通一个完整练习流程。原生JavaScript配合Node.js减少了前后端语言切换，SQLite方便本机持久保存，不需要额外部署数据库服务。运行时没有引入第三方依赖，安装比较简单。代价是HTTP路由、参数校验和页面状态等需要自己维护；项目扩大后，是否引入框架要根据维护成本决定，并不是原生方案始终更好。

### 问题9：系统怎么根据代码出题？是不是用了RAG？

目前没有向量数据库，也没有实现通常所说的向量检索式RAG。它先在浏览器按文件类型、目录和预算筛选代码，保留路径与片段，再由模型整理模块和引用，最后生成有范围和题量限制的问题计划。后续问答会带上当前考察点的相关材料。可以称为材料驱动的提问流程，不能说已经实现完整仓库索引或精准语义检索。

### 问题10：如果模型胡说或返回错误格式怎么办？

提示词会约束返回JSON，但后端仍会检查结构、允许动作、题量，以及引用能否在原回答或源码片段中找到。不符合要求时会在限制内尝试重新生成，失败则保留输入并提示重试。问题推进由程序控制，不完全交给模型决定。不过这些检查无法证明模型的技术判断正确，用户仍要对照代码和教材核实。

### 问题11：会不会一直追问，最后整轮都问不完？

项目练习先按照10、20、30分钟安排4、6、8个主考察点，最多允许5、8、11次回答。是否还能追问，要同时看当前考察点和剩余预算，并给后面的主问题留位置。这个时长只表示题量安排，不会因为用户查资料或模型等待就强制结束。复试有自己的5个计划点和最多12次回答的预算，不能混用成同一套数字。

### 问题12：自动保存如何防止覆盖？

前端会把保存请求按顺序发出。保存进行时如果又有新编辑，会标记还有待保存内容，前一个请求结束后再发送最新快照。后端记录版本号，更新时同时检查账号归属和版本；版本不一致返回冲突，提示备份与刷新，而不是直接覆盖。它能处理本机多窗口的一些覆盖问题，但不支持自动合并冲突，也不是分布式协同编辑。

### 问题13：用户记录和密码怎么保存？

访客记录保存在当前浏览器的localStorage，登录账号的记录保存在本机SQLite。密码使用随机盐和scrypt派生结果保存，不存明文；登录使用随机会话令牌，服务端保存令牌摘要，浏览器cookie设置HttpOnly和SameSite。保存接口还检查登录账号与提交归属。但数据库里的面试内容没有加密，应用也只定位为本机使用，没有实现生产环境的完整安全体系。

### 问题14：修改历史回答，为什么要创建分支？

因为一次回答会影响后面的追问。如果直接覆盖旧答案，却保留原来的后续问题和复盘，记录就可能前后不一致。创建分支时保留所选问题之前的对话，移除受这次修改影响的后续回答、判断和复盘，再从修改处继续。单题重答则只新增这一次回答就结束。原记录保留，既方便比较，也避免把润色后的内容误当成当时的原答。

### 问题15：免费额度耗尽时怎么切换模型？

服务端配置首选和备用名单。只有返回明确的额度耗尽错误时，才在同一次模型请求中尝试下一候选；本次服务运行期间会跳过已耗尽模型，重启后清除状态。密钥错误、欠费、普通权限错误不能当作单模型额度耗尽。图片请求使用独立的视觉模型名单，不会切到只支持文本的备用模型。应用读不到实时免费余额，是否用完即停还依赖服务商设置，因此不能承诺无条件免费。

### 问题16：怎么测试的？111项通过意味着什么？

自动测试覆盖会话推进、题量约束、输出与引用校验、账号保存和版本冲突、分支保留、刷题记录、模型切换与语音取消等逻辑。它们主要使用模拟模型响应；另外做过少量真实文本、图片和备用模型请求，以及页面操作验证。测试由AI工具辅助执行，我不把它描述成自己独立写完并手工验证的全部测试。111项通过说明已定义测试在当时环境下通过，不等于AI内容正确率，也不代表完整真人语音体验达标。

### 问题17：这是一个Agent或分布式系统吗？

更准确地说，这是一个接入大模型、由程序控制流程的本机练习应用。它会按步骤读材料、规划问题和处理回答，但没有一个能够自主决定任意工具调用的通用Agent，也不是多个服务组成的分布式系统。当前只有浏览器、一个Node.js服务和本机SQLite，目录名中出现agent不代表实现了相关架构。

## 六、准备面试时先掌握什么

先不背全部函数名，至少能脱稿解释下面五条路径：

1. 从上传文件夹到第一道问题：`source-material.js → materials.js → server.mjs → model.mjs → plan.js`。这些模块相互配合，并非所有步骤都是一次串行函数调用。
2. 从提交回答到推进问题：`app.js → server.mjs → model.mjs / model-routing.mjs → 会话更新`。
3. 从修改草稿到保存：`app.js → account.js → /api/records → store.mjs → SQLite`。
4. 从复盘到重新练一题：`review.js / practice.js → branch.js → 保存新记录`。
5. 从题组到错题回练：`academic-practice.js → study.js → study-review.js`。

还要能清楚说明三个边界：哪些工作由自己提出并参与验收，哪些实现借助AI；哪些现象已经观察或验证，哪些只是计划；哪些代码已理解，哪些仍需要查看后才能解释。

这份稿子用于帮助理解与组织表达，不应替代实际代码阅读或把尚未掌握的实现变成个人经历。
