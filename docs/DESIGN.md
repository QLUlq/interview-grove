# 面试验证引擎：框架融合与实现边界

本文保留开发过程中的设计取舍和阶段验证记录。各阶段的功能、端口和测试数量属于当时状态；当前版本以 [交付说明](RELEASE.md) 和根目录 README 为准。临时截图、脚本及测试产物集中在被 Git 忽略的 `artifacts/`，不属于运行所需文件。

## 采用的核心

问题由验证目标、事实锚点、追问方向共同组织。求职和考研共用状态机，场景配置持有考察节点和默认问题，信号表提供条件追问。规则运行留有原文线索和路由记录。

- 求职：经历与个人贡献 → 决策依据 → 结果口径 → 岗位动机。
- 考研：概念 → 依据 → 边界 → 迁移 → 本科经历与研究动机。
- 专项：保留旧版项目、缓存、并发题树及其历史记录。

## 对原讨论的取舍

1. “我们”等措辞只表明需要澄清，不证明缺少贡献。已经明确“我负责”等个人行动时不重复要求切换主语。
2. 数字不证明效果，没有数字也不意味着没有价值。询问基线、来源和周期，同时允许质性证据。
3. “接—拆—收”用于练习建议，不作固定答题格式或评分门槛。
4. 承认不熟悉时，考研可自愿联系已知知识；允许跳过。不能凭措辞判断诚实、造假或科研潜力。
5. 没有应用统一 40/35/25 评分权重。院校复试办法不同。当前纯文字版本也不能评价外语听说。
6. 不对政治信念、人格或“忠诚度”进行自动推断和评分。院校特定考核内容以后按公开办法人工配置。
7. 六类求职问题保留为题型元数据，不把“一面/二面/HR”当作所有单位统一采用的流程。当前提供一次通用面试，不声称已实现轮次权重调度。

## 当前真实能力

`public/framework.js` 是离线可验证的规则引擎。新增 `model.mjs` 提供可配置的服务端模型适配器；AI 模式把背景、锚点、对话发送给服务商，由模型生成追问、选路理由和逐字证据，再通过结构与预算校验更新会话。规则模式仍不做语义理解。两种模式均不进行外部知识核验或真实性判断。

每节点最多追问两次，同一规则不在该节点重复，总计最多接受 12 次回答。跳过、不确定、达到预算、正常完成分别记录动作。不能凭回答长度判断质量；当前仅用短回答启发式选择一次具体化问题，不产生分数。

新会话记录版本、锚点、完整回答、各节点信号（含原文片段）、路由动作与完成原因。复盘可展开查看追问线索并导出。旧版专项会话继续走原规则，不以新规则解释旧数据。

## 模型接入与后续验证

模型已可参与后续追问与证据提取，首问仍由题树提供；状态机限制问题预算、精确重复问题、选路和结束。模型输出经过结构验证、逐字引用检查，不能把“模型说已确认”直接当作事实正确。材料整理生成供用户确认的摘要，不提供独立事实核验；尚未实现语义去重或自动跨节点覆盖。没有密钥时不能宣称已实测模型表现。

先用回归样本验证重复追问、错误归因和跳过处理，再研究跨节点证据覆盖。样本学习只产生候选：需用户授权、脱敏、专业依据核实、评审、回归测试和可回滚版本发布。当前版本不自动更新树；下述个人练习版本新增的经验汇总仅使用固定词表组合。

# 2026-11-06 复盘工作台调整

本次沿用既有深绿、纸白与浅绿令牌，范围为复盘区域和模型调用可靠性。采用原生 HTML/CSS 与 details 展开，保持键盘操作及减少动画偏好；不添加与复盘无关的图片或三维场景。参考 lsf-website-design 的现有系统复用、主次层次、渐进展开及同尺寸核验方法。

- 从按方向堆叠原话，改成问题与回答逐题对应。每题的“为什么问这题”展示产生该题的上一轮选路依据与原话线索；开场题明确使用考察目的说明，不伪装成模型的内部思考。
- 用户原回答独立保留。“详细分析与润色”按需生成，包含有原话依据的优点与改进、忠实改写、待补充事实和单个练习任务。生成结果缓存于原有浏览器记录并进入下载文本，不因展开或刷新重复调用模型。
- 不用无依据分数和能力标签。改写保留未知、限制与未进行的测试，不把“无投诉”改成“已证明有效”，不将建议中的未来方案写成已经发生的经历。程序校验引用，过滤常见新增结论和未经依据的评分措辞；这不是全面事实核验，用户仍应核对改写。
- 可选引用不匹配时仅丢弃该引用；动作、问题与状态机约束仍严格验证。无效格式、重复问题、部分临时服务错误至多重试一次，两次请求共用45秒预算。密钥与额度错误不自动重试。保留草稿并显示等待秒数。
- 复盘目录、逐题问题/原答、浅绿展开入口、米色表达示范构成层级。平板分析改为单栏，手机保留底部再练入口，修正准备弹窗内部滚动。

验证：真实千问追问两轮约15.6秒、16.2秒；收紧约束后的详细分析一次约42.8秒。样本有限，不能推断长期成功率；模型耗时仍是未解决的速度瓶颈。375/768/1440截图与浏览器交互已检查；外部Gemini/Claude及Ego通道不可用，未声称完整技能流程或正式评分通过，使用当前模型的独立子Agent复核布局和内容风险。没有自动提交或发布。

# 2026-11-12 材料驱动的两条求职路线

新建入口只保留求职面试与考研复试，既有专项记录继续兼容。求职拆成项目技术练习与简历模拟面试：前者以源代码为考察依据，不询问岗位动机；后者以识别后的简历经历和可选岗位为依据。准备表单的经历摘要改成补充说明，读取概览和考察项独立展示，不再把代码压缩成一段履历后丢弃。

`public/source-material.js` 负责保留相对路径、跨目录抽样、排除依赖与明显凭据文件、兼容UTF-8/GB18030。上限80个文件、约11万字符，展示已读、截断、过滤与未读数量。`model.mjs` 先阅读代码并提取带引用的模块索引，随后生成本轮考察计划；代码引用必须出自给定片段，多行引用格式不一致时仅保留能够逐字匹配的一行，否则丢弃该引用。索引仍是模型生成的技术概括，不代表程序行为已被运行或完整核验。

`public/plan.js` 提供动态计划、材料结构验证与覆盖清单。整个小项目模式优先覆盖不同模块；负责模块模式按目录和技术关键词筛选关联材料，再规划实现与直接接口问题。补充里明确“只负责”或团队项目中的模块职责时，默认全项目范围也会收缩；找不到匹配材料时要求具体模块关键词。语义筛选仍可能不够精确，不宣称完整理解全仓库。

每轮可选10/20/30分钟，规划4/6/8个主要考察点，最多5/8/11次回答。主问题在开场前确定，advance直接进入下一道预规划问题，不由最新回答重写整条路线；每点最多补问一次，并为剩余主问题预留回答数量。预计时长只决定题量，不因自然时间流逝自动结束，避免学习时查资料被提前截断。旧时间到期记录支持保留已有回答并继续未问的主问题。复盘区分已回答、跳过、未问到和留待下一轮的材料要点；跳过不算掌握，全跳过不调用整轮分析。

简历逐项保留项目、实习和技能，并校验每段项目/实习被问题涉及。技能栏与项目技术栈不等同，跨经历引入技能时按假设场景询问。代码中的配置也不自动归为用户个人设计。每题可在提问旁展开其代码/简历出处；历史修改分支保留原计划和材料，清除后续回答和摘要。

读取的去身份化片段随当前用户记录保存；模型每次追问只取得当前考察项的相关文件片段，避免每轮重复发送全部代码。来源标识、索引、计划随账号保存并验证，最多8项的动态进度不再受旧4节点限制。原有考研和旧会话状态机保留。

千问接入针对阿里云qwen3.7-plus显式使用非深度思考模式，其他接口不传此专有参数，可用INTERVIEW_THINKING=true恢复。依据阿里云官方说明：https://www.alibabacloud.com/help/en/model-studio/deep-thinking 。真实Watch样本一次读取约28秒、规划约13秒、接受不确定回答后切换下一模块约3秒；不是长期延迟或成功率评测。

验证包含真实Watch目录读取与规划、LCD模块限定、浏览器上传Watch子目录、简历PNG识别与开场、原答分支和刷新恢复。独立浏览器使用合成简历与访客数据，未改动原嵌入式工程。新版服务在3001端口运行；原3000服务重启命令被自动审批以策略原因拦截，保留原服务。访客localStorage按端口分开，账号数据库共享。

# 2026-11-12 澄清事实与整轮复盘

新增 `public/interview-context.js`，只从用户已发送的回答提取带原文出处的事实边界。求职中的教程复现或学习实践转向实现理解、数据流和可观察结果；不把材料中的方案当作候选人的个人选型，不强迫没有测试过的用户提供量化指标。明确的错误归因问法触发校验重试，仍受原有45秒预算限制。当前提取与归因拦截依赖关键词和模型提示，不能覆盖所有语义，也不证明用户真正掌握了代码。

已结束的 AI 面试打开复盘后自动请求整轮摘要：已说明内容、待验证内容和一个可操作练习。每项引用必须逐字出自对应原回答，禁止把摘要当作能力评分或源码核验。生成中切换页面不会重复发起；失败保留原答并等待手动重试。结果进入访客或账号原有记录、文字导出和个人练习任务；修改分支时删除旧摘要并从保留的前缀重新建立事实边界。逐题详细分析与润色继续按需生成。

验证：合成回放包含本次“跟视频完成、卡顿原因未知”的澄清，真实千问后续转向显示缓冲区与I2C的数据流；真实摘要保留未知原因，并建议核对刷新调用链。单次回放不代表长期稳定性，模型生成仍有等待时间。

# 2026-11-06 个人练习与经验积累

沿用既有纸白与深绿、原生表单/弹窗/details，不扩展到整站视觉重做。首页只保留一个开始入口；两张说明卡介绍简练与实战节奏，在准备弹窗统一选择方向与模式。说明卡移除可点击与悬浮暗示。

- 账号按本机 SQLite 持久保存，访客仍使用原 localStorage，手动确认后才允许复制访客记录。账号保存串行合并最新草稿、检查版本冲突及账号归属；其他窗口切换账号时拒绝旧窗口写入、共享设置和模型请求。密码使用随机盐scrypt，cookie HttpOnly/SameSite；没有云同步、密码找回或生产部署能力。
- 简历图片与项目文件夹均可选。项目最多40片段，优先README、过滤隐藏目录/依赖/明显凭据文件，服务端再过滤常见凭据与联系标识。图片原样发送模型前必须由用户自行遮盖隐私。提取后仅保存确认过的摘要，不保存原文件；不能声称全项目理解或全面自动去隐私。
- AI每轮额外从固定技术词表与六种复查方向中筛选有用线索，不保存跨用户自由文本。个人页显示自己的标签、方向与详细复盘任务；后续模型上下文只读取当前账号。共享默认关闭，开启后需至少3个不同参与账号出现相同主题/方向组合，才在相关上下文中引用；关闭或删除即不再计入后续汇总。固定词表会限制经验表达能力，但避免将身份、原代码与原话带到其他账号。它不训练模型，不更新题树，实际提问质量提升尚需长期评测。
- 历史修改复制选中问题以前的记录，移除后续证据、路线与润色结果；原回答预填到新分支，再次发送才进入新路线。多级分支保留来源与根会话，历史按来源缩进归组。

验证：34项自动检查通过，涵盖账号隔离、保存并发/冲突、跨窗口账号归属、共享阈值/撤回、标识过滤、材料格式、记忆白名单和分支状态截断。浏览器真实千问调用成功完成合成简历PNG＋项目文件夹提取、两次实战追问（含修改后的分支）及一次复盘；退出、服务重启、重新登录后原记录与分支恢复。375/768/1440布局经过开发自查与一次独立子Agent复查。复查提出的说明卡悬浮与手机按钮换行已修复；未声称正式美学评分或技能完整流程通过。


# 2026-11-12 单条删除与单题重练

历史列表将打开记录与删除拆为并列按钮。删除需要确认，只移除当前空间所选的一条；不会级联删除已有分支。中间来源删除后重新连接仍在的上级，根记录删除后分支独立展示。删除后的账号数据沿用串行、带版本校验的保存通道；分析进行中暂不允许删除，避免替换记录对象时遗失尚未落盘的结果。

登录后的练习方法页改为具体问题清单：来源、原问题、原回答、一个目标。优先用整轮与逐题建议，补充明确不懂或跳过的回答；没有建议的记录也能从原回答自查开始。不把继承的分支前缀重复列为新任务，也不把 AI 标签当作能力判定。

“重答这一题”保留问题之前的上下文，只新增一次回答，直接结束并保存为分支；草稿自动保存到当前空间。结果展示前后对照，AI 建议须主动点击，失败不影响重答保存。已重答与待练分开展示，不推断已掌握；来源被删除后仍能从记录复盘或保留的重答入口查看结果。单题分支不自动请求整轮摘要，常规复盘的修改分支仍沿原有多题路线继续。

验证：77项自动测试覆盖删除后的分支保留、账号隔离、草稿与重答保存、任务去重、分析兼容与不自动请求摘要；独立临时 SQLite 内存账号完成浏览器删除确认/取消、刷新恢复、单题重答、对照与按需建议流程，375与1440宽度检查。浏览器建议使用可控模拟服务，未据此宣称新一轮真实模型质量已验证；用户已有记录未被删除或改写。


# 2026-11-12 免费额度备用模型

统一请求层移至 model-routing.mjs。文本首选与有序备用名单、图片专用名单分别配置。只对明确的单模型额度错误执行切换，普通限流保持一次重试，账号欠费、鉴权与权限错误停止。单次请求共享45秒时限，不改写用户材料、问题计划或原回答；全部候选耗尽后保留输入等待配置更新。

耗尽列表和各模态的成功模型保存在服务内存，跨请求共享，重启清除；不是后台额度查询，也不探测名单之外的模型。实际请求拥有独立 usage 归属，防止并发文本和图片识别相互覆盖模型标签；页面收到切换原因后提示新模型。Qwen3.5/3.7 Plus在支持的阿里云接口默认禁用思考；切到 qwen-max 时不携带该参数。视觉路由不使用纯文本候选。

根据用户提供的额度截图，当前首选改为 qwen3.5-plus-2026-02-15，文本备用 qwen-max；图片识别仅用已验证的 qwen3.5-plus-2026-02-15。未接入截图中的专用OCR、意图识别或尚未核实接口能力的模型。保持服务商“用完即停”设置；程序无法保证未知候选免费，也不会修改服务商计费开关。

验证：84项自动测试通过，覆盖额度识别、同请求切换、后续跳过、全耗尽输入保留、不同错误分类、图片名单及并发归属。真实小请求验证了首选模型JSON、128px合成图JSON识别，以及模拟首选403后真实 qwen-max 成功的完整请求路径（不声称首选实际已经耗尽）。独立内存服务浏览器验证切换提示、模型标签和只新增一次回答；未改写用户历史。小请求成功不代表完整面试质量已经重新评测。
